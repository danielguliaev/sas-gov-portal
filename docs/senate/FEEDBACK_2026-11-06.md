# Доработка по фидбеку

Уточнения пользователя имеют приоритет над v1.1 ТЗ.

- Вступление в силу: стандартные 14 дней после подписи губернатора, немедленно после подписи с оговоркой о неотложности, либо выбранная дата с установленной формулировкой. Отдельного варианта «с момента подписания» нет.
- Преамбула необязательна. Соавторов выбирают по именам без численного ограничения, подтверждение соавторства сохраняется.
- Поправка содержит текст и параметры статьи библиотеки, включая санкции, категории, пользовательские поля и юридические связи. Научные сноски не изменяются.
- Кодекс и место новой статьи выбираются из библиотеки. В интерфейсе используются обозначения вида PEN §187.
- Проверка показывает преамбулу, строку «НАРОД ШТАТА САН АНДРЕАС ПОСТАНОВЛЯЕТ СЛЕДУЮЩЕЕ:», последовательно пронумерованные блоки изменений и положение о вступлении в силу.
- Незавершённый редактор хранится локально отдельно для каждого персонажа и проекта, включая шаг и поправки.
- Повестка комитета содержит дату и время и появляется в календаре.
- Выборы про темпоре являются предметом общей повестки. Инициирует только лейтенант-губернатор. Он также формирует повестку, если нет действующего про темпоре.
- Кворум берётся из настроек суперадминистратора. Составитель повестки его не выбирает.
- Голосование открывается при публикации. Все результаты скрыты до закрытия, затем доступны поимённо. Публичная дата заседания независима от ООС времени закрытия; ООС время не выдаётся обычному читателю.

## Решения по устройству

Полный текст документа вычисляется сервером из преамбулы и блоков, сохраняется в метаданных редакции и используется в карточке, PDF, JSON и опубликованном акте. Альтернатива с генерацией только в браузере отвергнута, поскольку дала бы разные тексты в экспорте и повестке.

Выборы используют общий список предметов, общие сроки, состав голосующих и отсутствие на всём заседании. Отдельные данные кандидатов сохраняются в senate_elections. Старые выборы мигрируют в предметы своих прежних повесток без удаления истории. Альтернатива с отдельными повестками и перекрёстными ссылками сохраняла бы прежнее ограничение.

Локальный кэш не заменяет сохранённую серверную редакцию. При несовпадении версии редактор сообщает о конфликте и сервер отклоняет устаревшее сохранение.

## Новые замечания: только запись, реализация не разрешена

Пользователь просит собирать этот блок фидбека без изменения кода и данных портала.

1. Предложение пользователя: использовать сокращение кодекса как его ID. Для Penal Code вместо указанного пользователем `penal-demo` использовать `PEN`. При последующей реализации смена существующего ID должна сохранять ссылки на статьи, поправки, редакции и другие связанные записи. Текущее значение ID в базе в рамках записи фидбека не проверялось.
2. Ошибка генератора: в тексте законопроекта выводится ID кодекса вместо полного названия. Требуемое отображение: `Penal Code`. Обозначение статьи в интерфейсе остаётся `PEN §187`.
3. Вкладка редакций и история действий должны быть читаемыми. На приложенном скриншоте видны технические названия событий, JSON с параметрами и внутренние идентификаторы персонажей.
4. Вместо `draft_created`, `consultant_report`, `committee_decision`, `senate.agenda.published`, `senate.vote.closed` показывать понятные русские названия действий. Вместо JSON показывать связное описание: куда подан проект, какая редакция рассматривается, что рекомендовал консультант, какое решение принял председатель, каковы итоги голосования.
5. В авторстве редакций и событий показывать имя персонажа. Для автоматических действий использовать понятное обозначение системы. Названия комитетов и заседаний выводить вместо их внутренних ID; связанные документы открывать по ссылкам.

Примеры желаемой истории: «Проект подан в Rules Committee. Редакция № 1», «Консультант рекомендовал окончательно отклонить проект», «Председатель рекомендовал проект к принятию», «Голосование завершено. Проект отклонён: за — 0, против — 3, воздержались — 0. Присутствовали 3 сенатора при кворуме 1».

Источник: сообщение пользователя и скриншот от 06.11.2026. Этот блок не означает, что перечисленные ошибки уже исправлены.
