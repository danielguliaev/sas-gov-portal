# Портал Сената

Сенат доступен по `/senate` и использует существующий процесс FastAPI, SQLite и вход OIDC. Внешний вид воспроизводит сайт Сената Калифорнии, независимо от оформления правовой библиотеки. Эталон сохранён в `references/senate-ca-home-2026-11-05.png`, источники графики перечислены в `web/senate-assets/sources.json`.

## Хранение и границы

Проекты, редакции, события, заседания и голоса остаются в существующих таблицах `bills`, `bill_revisions`, `bill_events`, `legislative_sessions`, `votes`, `vote_choices`. Миграции добавляют связанные таблицы с реквизитами Сената. Это сохраняет совместимость со старым демонстрационным API, где вставка записей зависит от числа столбцов.

Рассматривались отдельный сервис со своей базой и расширение существующего приложения. Отдельная база потребовала бы синхронизировать стабильные ID законов, права и историю. Выбран общий процесс с отдельными маршрутами `/api/v1/senate`, чтобы подача проекта, редакция, событие и аудит сохранялись одной транзакцией.

`app/senate.py` владеет проектами, членством, настройками и комитетским рассмотрением. `app/senate_sessions.py` владеет повесткой, составом голосующих, кворумом и результатом заседания. `app/senate_pdf.py` формирует PDF с кириллицей и нумерацией страниц. Интерфейс использует самостоятельные `senate.html`, `senate.css`, `senate.js`.

`app/senate_officers.py` хранит выборы Pro Tempore и предложения о составе комитетов. Флаги комитета выдаются только после принятия соответствующего предмета. Исправления завершённых голосований переводят результат на проверку; дальнейшее решение администратора требует отдельного основания. Исправление старого заседания не может перезаписать более новую действующую повестку.

`app/senate_document.py` формирует шапку и текст документа; `app/senate_presentation.py` разрешает исторические ссылки на кодексы и формирует читаемую историю. Авторы документа хранятся в метаданных, а `bills.author_id` сохраняет создателя записи. Сервер фиксирует выбранное правило голосования в опубликованном предмете; числовой порог берётся из настроек категории.

`app/senate_agendas.py` отвечает за общий каталог, просмотр повесток, свободные обсуждения, адреса и изменения расписания. Обсуждения имеют собственные записи и не создают фиктивных законов или голосов. Перенос открытого заседания архивирует бюллетени в `senate_voting_rounds`, очищает текущие голоса и начинает следующий раунд. Отмена не применяет результаты. Прошедшие стадии и аудит сохраняются.

`app/code_identity.py` выполняет миграцию ID кодексов к уникальным сокращениям с отложенной проверкой внешних ключей. ID статей и редакций не меняются. Таблица `code_id_aliases` разрешает прежние ID в сохранённых поправках; исторические JSON остаются исходными. При совпадении сокращений миграция не объединяет кодексы.

Старые команды законопроектов отклоняют доступ к предметам нового Сената. Иначе через старый маршрут можно было бы прочитать чужой черновик, заменить опубликованный текст или закрыть голосование без кворума.

## Уточнения владельца от 05.11.2026

- Срок на отчёт консультанта и срок на рассмотрение после отчёта настраиваются отдельно суперадминистратором.
- `Not Pass` окончательно отклоняет законопроект.
- Сенатор может изменить любой вариант голоса до конца заседания, включая «Отсутствовал».
- «Отсутствовал» распространяется на все предметы заседания.

При новом обычном голосе после отсутствия пользователь восстанавливает присутствие. Остальные предметы требуют нового голоса, прежние голоса не восстанавливаются автоматически. Исходные события сохраняются в истории.

Другие вопросы раздела 23 ТЗ остаются предложениями, если владелец не утвердил их отдельно. Первая настройка состава Rules Committee выполняется администратором, а административные изменения требуют записи в аудите.

## Запуск и проверка

На Windows портал запускается файлом `start_senate.bat`, адрес `http://127.0.0.1:8001/senate`. Запуск не обновляет Git и не переключает ветки. Для production требуется существующий OIDC-контракт, режим демонстрации в production запрещён.

Проверки выполняются на временной базе. Основная библиотека не меняется, импорт принятых поправок не выполняется. История Сената исключена из шестимесячной очистки общего аудита.

```powershell
.\.venv-portal\Scripts\python.exe -m pytest tests/test_senate_core.py tests/test_senate_sessions.py tests/test_senate_integration.py -q
.\.venv-portal\Scripts\python.exe -m pytest tests/test_senate_officers.py -q
.\.venv-portal\Scripts\python.exe -m scripts.verify_senate
```

Для повторной загрузки исходных изображений и шрифтов доступен `python -m scripts.fetch_senate_assets`. Он требует сети. Законодательные данные и реальные контакты Калифорнии скрипт не импортирует.

Проверка полного процесса создаёт временную базу и проходит подачу двух проектов, соавторство, отчёт, комитетскую повестку, решение, пленарную повестку, каскадное отсутствие, смену голосов, закрытие и стенограмму. Затем проверяет сохранность библиотеки и экспортирует PDF и JSON в `.senate-preview/acceptance`. PDF показывает время в переданном часовом поясе пользователя; JSON сохраняет UTC.

## Границы текущей версии

- Опубликованная пленарная повестка неизменна. Для нового рассмотрения создаётся новая повестка. Редактирование опубликованной повестки с созданием её новой редакции не реализовано.
- Выборы про темпоре включаются в общую повестку вместе с законопроектами. Повторная попытка сохраняет ссылку на предыдущую.
- Стенограммы хранятся как версионированный текст. Отдельного хранилища исходных файлов нет.
- Новые типы документов поддерживают шаблон и обязательные поля. Произвольные новые этапы процесса и собственные операции над законами требуют расширения модели.
- Возврат на доработку, в отличие от окончательного `Not Pass`, остаётся неподтверждённым правилом. Команда блокируется до явной настройки `disputed_policies`.
- На главной используется печать проекта вместо отсутствующего портрета должностного лица. Для обращения Pro Tempore и собственного фотоматериала требуется предоставленное содержание. Архитектурные фотографии подписаны как образец Калифорнии.
- Вход OIDC требует настроенного поставщика. Сервис выборов соседнего портала, импорт принятого закона в библиотеку, вето, электронная подпись и тайное голосование не входят в эту версию.
