# Реализация ТЗ 1.0: запуск, контракты и ограничения

## Назначение

Пилотная версия законодательной сети вымышленного штата Сан-Андреас. Все автоматически создаваемые статьи — **демонстрационные**, не действующие юридические нормы. Переводы иных законов из пользовательских файлов не импортируются автоматически.

## Локальный запуск

Python 3.11+:

    python -m venv .venv
    source .venv/bin/activate
    python -m pip install -e ".[test]"
    uvicorn app.main:app --reload
    pytest -q

Сайт доступен по адресу http://127.0.0.1:8000, интерактивная документация API — http://127.0.0.1:8000/docs, OpenAPI — /openapi.json. На Windows используется соответствующий скрипт активации venv. Для локального входа выберите тестовую роль в верхней панели.

## Архитектура

Сервер: FastAPI, SQLite/WAL, миграции db/001_initial.sql, db/002_revision_labels.sql и db/003_library_acts.sql, транзакции BEGIN IMMEDIATE, ограничения уникальности и внешних ключей. Адаптивный интерфейс: web/index.html, web/style.css, web/laws.css, web/admin.css, web/app.js, web/admin.js, web/search.js, web/notes.js и web/acts.js. Постоянные ID независимы от юридических номеров. Новые юридические редакции добавляются отдельными строками со снимками категорий, полей, санкций и связей.

Переменные окружения: DATABASE_PATH, APP_ENV, AUTH_MODE, OIDC_ISSUER, OIDC_AUDIENCE, OIDC_JWKS_URL, OIDC_ROLES_CLAIM. В production демонстрационная авторизация запрещена, допускается только OIDC RS256/JWKS. Веб-интерфейс OIDC/PKCE и обмен авторизационного кода на токен реализованы как настраиваемый адаптер; реальные адреса, регистрация клиента, роли провайдера и совместная проверка требуют интеграции с другой командой.

## Интерфейс портала законов

Стартовая страница / оформлена в стиле государственного правового реестра: поиск, карточки трёх юрисдикций, метрики действующего содержимого, кодексы, недавно созданные редакции и перечень прочих ведомственных ресурсов без активных ссылок. Для них в будущем предусмотрены самостоятельные сайты. /laws — каталог кодексов с фильтрами по уровню права и локальным поиском по наименованию; /jurisdictions/{id} открывает этот каталог с выбранным уровнем. Числа статей и разделов берутся из GET /api/v1/codes и /api/v1/library/overview, а не захардкожены.

Маршруты /codes/{id} и /codes/{id}/nodes/{node_id} показывают содержимое иерархии, хлебные крошки, вложенные разделы, список статей по 12 с курсорной загрузкой и индикатор количества загруженных текстов. В боковой навигации нет служебного пункта «Статьи корня кодекса»: корневые статьи идут непосредственно под названием кодекса после корневых структурных элементов на том же уровне. Метаданные для бокового индекса предоставляют /codes/{id}/root/article-index и /nodes/{id}/article-index с курсором; API не передаёт полный текст при формировании индекса. /articles/{id} открывает постоянный адрес конкретной статьи, вычисляет позицию чтения сервером и поддерживает соседние статьи. /search?q=... принимает адресный поисковый запрос; для юридических ролей доступны фильтры кодекса, категории и юрисдикции. Кнопка печати отсутствует согласно REQ-087; для стандартной браузерной печати сохранена базовая таблица стилей.

В мобильной версии навигация открывается отдельной кнопкой и закрывается по затемнённой подложке или Escape; присутствуют ссылка для пропуска навигации, основные клавиатурные состояния и комбинация Ctrl/⌘+K для перехода к поиску. Сохранение избранного и масштаб шрифта связаны с серверными настройками. Гостевой экран предлагает выбрать доступную роль и не запрашивает юридические тексты. В библиотеке пользователю предложены только роли «Читатель», «Юрист», «Суперадминистратор». Роли отраслевых порталов сохранены на сервере как отдельные внутренние полномочия и ещё потребуют разнесения по самостоятельным сайтам. Центр уведомлений библиотеки принимает только portal_id=library; чужие источники не отображаются и их уведомления нельзя отметить прочитанными через библиотечный API.

В CI отдельный тест Chromium проверяет загрузку гостевой главной страницы, вход с тестовой ролью, каталог, чтение, поиск, мобильную навигацию, создание типов и узлов иерархии, корневой индекс статей и отсутствие JavaScript-ошибок. GitHub Actions прикладывает изображения law-portal-desktop.png, law-portal-reader.png, law-portal-mobile.png в артефакте portal-law-ui. Локально: установите пакет с опцией browser, затем python -m playwright install chromium, после чего выполните RUN_BROWSER_TESTS=1 pytest -q tests/test_browser.py.

## Изменения интерфейса по замечаниям

По согласованию введено наименование «Правовая библиотека штата Сан Андреас». Удалён круглый знак SA из шапки, общая демонстрационная плашка и пользовательские бейджи; в футере установлен текст «Copyright © 2026 State of San Andreas» и удалена ссылка на документацию API. В боковой панели прочие ведомственные сайты перечислены без активных ссылок. Они не являются внутренними разделами правовой библиотеки. Администратор может создать новый тип уровня, выбрать допустимые типы родителей, создать часть/раздел в корне или под допустимым узлом и изменить номер/заголовок существующего узла. В редакторе статей выбирается родительский структурный элемент либо корень кодекса; при переносе статьи сохраняется постоянный ID, а интерфейс открывает статью в новом местоположении. Сводка выполнения требований UI-001…UI-008 и оставшиеся части находятся в docs/UI_FEEDBACK_TZ.md.

Внутренние тестовые данные сохраняются отдельно от юридического статуса нормативных актов. Сокрытие демонстрационных пользовательских меток не означает подтверждения действительности тестового текста.

Для локальной Windows-сборки доступен start_portal.bat (двойной щелчок в папке проекта, Python 3.11/3.12; создаёт окружение .venv-portal). После обновления репозитория обновляются и интерфейс, и серверные API.

## Основной API

Базовое чтение (требуется аутентификация): GET /api/v1/jurisdictions, /portals, /codes, /codes/{code_id}/tree, /codes/{code_id}/root/articles, /nodes/{node_id}/articles, /articles/{article_id}, /articles/{article_id}/position, /articles/{article_id}/adjacent, /articles/{article_id}/relations, /search, /precedents, /portal-publications, /bills. Выдача статей содержит курсор продолжения next_cursor.

Для lawyer/superadmin доступны история версий и снимки конкретной редакции, поля категорий, расширенные поисковые фильтры, /me/favorites, /me/notifications, примечания к выделению текста в определённой редакции. Настройки масштаба текста хранятся через /me/preferences. Обычным читателям юридические расширенные поля сервер не возвращает.

Запись superadmin: POST /codes, /codes/{code_id}/hierarchy-types, /codes/{code_id}/nodes, /articles, /articles/{id}/revisions, /relation-types, /relations, /categories, /categories/{id}/fields, /category-fields/{id}/options; PATCH /hierarchy-types/{id}, /nodes/{id}, /category-fields/{id}, /field-options/{id}. Предусмотрены предпросмотр и подтверждение переноса узла, пересортировка, предпросмотр и удаление типов иерархии с поднятием детей, каскадное архивирование/восстановление, в том числе атомарная замена конфликтующей статьи.

Исключительное редактирование: POST /articles/{id}/edit-lock создаёт блокировку конкретной сессии и выдаёт токен; /edit-lock/heartbeat продлевает владение; DELETE /edit-lock освобождает; /edit-lock/revoke требует подтверждение и допускает только собственную блокировку superadmin. Сохранение проверяет lock_token, editor_session_id и base_revision_id, серверное истечение блокировки — 5 минут.

Официальные публикации portal_publisher: POST /portal-publications и /portal-publications/{id}/publish. Только публикация не меняет текст кодекса. Library_editor/superadmin может проверить публикацию через /editorial-reviews и /editorial-reviews/{id}/confirm: нужны блокировка и подтверждённый консолидированный текст; происхождение сохраняется в новой редакции. Судебные прецеденты квалифицируются через /portal-publications/{id}/precedent. Законопроекты и голосования доступны отдельными маршрутам /bills; допустимые переходы конфигурируются через BILL_TRANSITIONS_JSON и изначально демонстрационные.

## Инварианты

Уникальность действующего номера статьи проверяется в пределах кодекса, в том числе по нормализованному номеру, без влияния на архивные номера. У обвинения должен быть один класс felony/misdemeanor/infraction; произвольные поля необязательны. Наличие санкции добавляет категорию «Мера наказания», все отсутствующие границы санкций остаются null, а не нулём. Одна статья наказания может быть связана не более чем с одним внешним обвинением в активном состоянии. Архивирование отключает связи без автоматической повторной активации; история изменений сохраняется. Рискованные массовые операции требуют актуальный preview_hash, confirm:true и заголовок Idempotency-Key; для конфликта номера при восстановлении отдельно необходим confirm_swap:true. HTML очищается на сервере.

## Дополнительные замечания UI-011, UI-012 и L10N-003

Раздел /admin/hierarchy переработан в рабочую область с самостоятельными сценариями «Уровни структуры», «Переместить раздел», «Порядок разделов». Уровни выбираются компактным списком; справа отображается редактор одного уровня и видимые правила допустимой вложенности. Исключение уровня вынесено в опасные действия с предварительной проверкой и отдельным подтверждением. Перемещение и ручная сортировка сохранены; кнопки изменения порядка доступны с клавиатуры.

Раздел /admin/relations также разделён на «Виды и правила», «Связать статьи» и «Просмотр и восстановление». Настраивается один выбранный вид связи, назначение использует поиск исходной и целевой статьи, просмотр показывает действующие и ранее отключённые отношения отдельно. Выборочное восстановление допускается только после проверки совместимости сервером.

В интерфейсе читаются русские названия классов обвинения: «Тяжкое преступление» (felony), «Проступок» (misdemeanor), «Нарушение» (infraction). Идентификаторы базы и API не изменены. Структурные и юридические изменения остались под серверной проверкой, с аудитом.

## Улучшения работы с большими кодексами и аудитом

REQ-068: настольная боковая навигация сворачивается в компактный столбец без скрытия кнопки разворачивания. Состояние хранится в пределах сессии браузера и не мешает выдвижному меню мобильных устройств.

REQ-075—REQ-076: запись истории чтения привязана к реальному адресу и положению прокрутки, восстанавливается после повторной курсорной загрузки карточек при Back/Forward. Прямая ссылка на статью имеет приоритет над посторонней позицией. Браузерный тест проверяет возврат к позиции в главе из пятнадцати статей. AT-12: новый браузерный сценарий проверяет, что публикация в другой вкладке не меняет открытый текст до явно запрошенного обновления страницы.

REQ-124: новый API GET /api/v1/codes/{code_id}/structure-index ограничен прямыми дочерними узлами parent_id и отдаёт страницы по cursor/limit с сохранением юридического и ручного порядка. Запросы защищены проверкой существования родителя и привязкой курсора к области. Читательское дерево теперь загружается лениво через этот индекс. GET /tree?include_nodes=false возвращает только сведения о кодексе и типах, а /node-context — путь к открытому разделу. Дочерние узлы и плитки содержимого подгружаются по cursor/limit; полная выгрузка структуры используется только в отдельных административных операциях выбора родителей. Нагрузочная проверка десятков тысяч узлов ещё необходима.

REQ-121: миграция db/005_audit_outcomes.sql добавляет к аудиту источник и результат действия, а также HTTP-статус. Успешные записи транзакционны с изменением юридических данных; неудачные записи авторизованных администраторов журналируются отдельно после отката основной операции. Содержимое запроса и токены в эти записи не попадают. Интерфейс журнала показывает дату, источник и состояние. Тесты проверяют разграничение доступа, отклонённый конфликт и сохранение только безопасных сведений.

## Обновление администрирования кодексов и категорий (UI-009, UI-010)

Раздел /admin/codes содержит заметную кнопку «Создать кодекс» и мастер регистрации. Та же команда доступна непосредственно из /laws для суперадминистратора. Название, сокращение, юрисдикция и начальная схема уровней выбираются перед созданием. Сервер в одной транзакции сохраняет кодекс и (по выбору) типы «Часть», «Раздел», «Глава», «Подраздел». Допустим вариант пустой иерархии для ручной настройки. Имена в одной юрисдикции проверяются без учёта регистра; пустые значения и неверный шаблон отвергаются. Новые пользовательские кодексы не получают тестовую метку автоматически. После регистрации открывается постоянный адрес кодекса.

REQ-022: у кодекса появились необязательные реквизиты публикации: publication_issuer, publication_reference, published_at. Метаданные можно вводить при создании, а позднее изменять через административную карточку кодекса (PATCH /api/v1/codes/{id}). Идентификатор, юрисдикцию и статус кодекса нельзя изменять через эту форму. Сервер проверяет дату в формате YYYY-MM-DD, хранит старые кодексы без выдуманных реквизитов и журналирует изменение. Миграция db/004_code_publication.sql добавляет колонки к существующей SQLite-базе и применяется автоматически при запуске; проверяется повторный запуск и сохранение старых записей.

Страница /admin/categories переосмыслена как двухпанельная рабочая область: слева поиск и выбор категории, справа только выбранная категория с компактными полями, раскрываемыми индивидуально. Создание категории, изменение названия, создание и обновление поля, добавление/переименование/скрытие значения справочника размещены по этапам вместо длинной ленты открытых редакторов. Для существующих полей показывается ограничение изменения их типа; сервер дополнительно отклоняет пустые и повторяющиеся имена категорий, полей и значений, сохраняя прежнюю историческую модель. Категория и выбранный кодекс могут сохраняться в URL страницы; узкий экран получает последовательное расположение блоков.

Существующий Chromium-тест проверяет пользовательские пути создания нового кодекса и категории, добавления поля выбора, создания и изменения справочного значения и отсутствие горизонтального переполнения административной страницы на ширине 900px. Отдельный тест Chromium для AT-11 проверяет пагинацию 15 статей, временный сбой сетевого запроса, сохранение 12 уже загруженных карточек, повторную загрузку без дублирования и прямую ссылку на глубокую статью. Отдельные тесты сервера проверяют валидацию названий, полномочия, уникальность и миграцию v4.

## Актуальная реализация библиотеки

Административная область `/admin` содержит отдельные экраны создания кодексов, управления типами иерархии и совместимостью уровней, ручной/автоматической сортировки, переносов и исключения типов с предварительным просмотром, справочников категорий и их полей, юридических связей, архивирования и восстановления с отдельным подтверждением, а также закрытого журнала действий. Для крупных групп предусмотрено явное управление порядком; переносы и архивные операции валидируются на сервере. Новый редактор статей поддерживает HTML-режим и визуальное форматирование, типизированные дополнительные поля и выбор местоположения.

Расширенный поиск `/search` включает точный номер, категорию, кодекс и юрисдикцию, уголовный класс, наличие санкций, числовые диапазоны санкций, пользовательские поля, режим архивных статей и исторических редакций `/search/revisions`. У юриста присутствуют избранное, привязанные к фрагментам редакций научные примечания и просмотр исторического состояния справочников. Для архивной статьи есть отдельное читаемое представление.

Каталог `/acts` отображает опубликованные самостоятельные нормативные акты. Они включаются в библиотеку только по прямой публикации суперадминистратора либо после его явной квалификации уже опубликованного внешнего документа. Этот шаг предотвращает автоматическое объявление новостей или судебных решений законодательством. Сведения хранятся в `library_acts` (миграция v3); доступны архивирование, восстановление, постоянные ссылки и аудит.

API будущей игровой интеграции находится в `/api/v1/integration`, имеет отдельную read-only аутентификацию по сервисному ключу и не содержит игровой логики расчёта наказаний. Для сервера добавлены защита от чрезмерной частоты запросов (429), заголовки безопасности, счётчики и длительность запросов, проверка готовности и сервис резервного копирования SQLite с проверкой целостности и возможностью восстановить снимок.

Полные команды эксплуатации, необходимые внешние параметры OIDC и ограничения развертывания описаны в [OPERATIONS.md](OPERATIONS.md). Актуальный анализ пунктов ТЗ — [REQUIREMENTS_STATUS.md](REQUIREMENTS_STATUS.md).

## Ограничения и внешние зависимости

По прямому указанию заказчика самостоятельные сайты правительства, законодательного органа, секретаря штата, судебной системы и муниципалитета **отложены**. API их публикационных процессов пока остаётся серверным заделом и не считается поставкой таких сайтов. Полный юридический корпус в действующий каталог не импортировался, что соответствует REQ-004; существующие тестовые тексты нельзя считать действующими правовыми нормами.

Не завершены подключение реального IAM другого разработчика, многосерверная production-инфраструктура, внешний HTTPS-proxy, расписание и удалённое хранение бэкапов, централизованные журналы/алерты, тесты полной доступности, устойчивости к большой нагрузке и полного списка AT-01…AT-20. Восстановление сессии браузера на очень больших главах, сложные вложенные операции, старые редакции, созданные до миграции снимков справочников, требуют дополнительной приёмки. Утверждать промышленную готовность до внешней интеграции и проверки всех сценариев нельзя.

Автоматические проверки доступны в `tests/` и `.github/workflows/tests.yml`; результат CI относится к конкретному SHA.
