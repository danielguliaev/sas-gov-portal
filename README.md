# Правовая библиотека штата Сан Андреас

Система законодательных ресурсов вымышленного штата Сан-Андреас по ТЗ 1.0 (04.11.2026).
Стартовые кодексы и тексты — демонстрационные, а не действующее право.

## Портал Сената

Для проверки нескольких игроков доступна отдельная панель `/accounts`. В локальном режиме подготовлены 20 аккаунтов, по два персонажа у каждого. Нажмите «Войти тестовым администратором», выберите аккаунт, настройте общие права и полномочия персонажа. Кнопки перехода открывают Сенат или библиотеку от его имени. Существуют отдельные профили, добавление персонажей, отключение аккаунта и журнал изменений. Регистрации и связи с игрой пока нет; в режиме OIDC и production тестовая панель и переключение недоступны. Повторный запуск не сбрасывает выданные права и изменённые имена.

В ветке `feat/senate-portal` доступен самостоятельный интерфейс Сената по ТЗ 1.1. Оформление воспроизводит сайт Сената Калифорнии. Библиотека и Сенат используют одну базу, вход и стабильные идентификаторы статей.

На Windows запустите **start_senate.bat**, затем откройте `http://127.0.0.1:8001/senate`. Запуск не переключает ветку и не выполняет `git pull`. Вход в локальной версии находится в верхней строке. В меню «Локальная демонстрация» доступны тестовые учётные записи; в режиме OIDC используется внешний вход.

Реализованы черновики и соавторство, редакции и поправки к библиотеке, комитетские отчёты и повестки, решения председателей, пленарное голосование, выбор Pro Tempore, предложения о составе комитетов, профили, новости и архив. Суперадминистратор управляет флагами и группами прав, категориями, шаблонами, сроками и кворумом. Административные исправления сохраняют прежние значения и основание.

Срок на отчёт и срок на рассмотрение после отчёта настраиваются отдельно. `Not Pass` окончательно отклоняет проект. «Отсутствовал» действует на всю повестку; до конца заседания голос можно изменить. PDF и JSON содержат историю, а принятие проекта не изменяет автоматически статьи библиотеки.

Для первых комитетских действий суперадминистратор назначает консультанту `committee:rules`, а председателю сенаторский флаг, `committee:rules` и `chair:rules`. Для пленарной повестки назначается Pro Tempore. Выборы Pro Tempore инициирует пользователь с флагом Лейтенант-Губернатора; до публикации в настройках требуется выбрать согласованное правило выборов.

Проверка полного процесса на временной базе:

```powershell
.\.venv-portal\Scripts\python.exe -m pip install -e ".[test]"
.\.venv-portal\Scripts\python.exe -m scripts.verify_senate
.\.venv-portal\Scripts\python.exe -m pytest -q
```

Проверка сохраняет настоящие экспорты в `.senate-preview/acceptance`, основную базу не меняет. Подробности реализации и оставшиеся ограничения находятся в [документации Сената](docs/senate/ARCHITECTURE.md).

## Windows: запуск двойным нажатием

Для локального запуска портала из Проводника используйте файл **start_portal.bat** в корне репозитория. Его можно запускать двойным нажатием. Скрипт:

- Проверяет Python 3.12 (или 3.11); при его отсутствии показывает инструкцию установки.
- Создаёт собственное виртуальное окружение `.venv-portal`, не затрагивая прежнее `.venv`.
- Устанавливает зависимости при первом запуске и повторно использует их после этого.
- Запускает сервер на 127.0.0.1:8000 и открывает страницу в браузере, когда сервер готов.
- Если сервер уже запущен, просто открывает существующую страницу.

При первом запуске нужен интернет. Для остановки сервера закройте окно консоли или нажмите Ctrl+C. Если файл находится в «Загрузках», скрипт также попробует найти проект в `%USERPROFILE%\sas-gov-portal`; для других расположений поместите файл непосредственно в корень проекта.

Скрипт предназначен только для локальной демонстрационной версии Windows, не для публикации в интернете.

## Что можно делать в библиотеке

После входа читатель видит кодексы, отдельные нормативные акты, иерархические разделы, карточки статей, судебные прецеденты и поиск. Юрист дополнительно работает с профессиональными фильтрами (уголовные классы, санкции, пользовательские поля), архивом редакций, научными примечаниями и личным избранным. Суперадминистратор создаёт кодексы и разделы, настраивает категории и поля, вручную управляет юридическими связями и структурным порядком, архивирует и восстанавливает материалы с предварительным просмотром.

Административная область: `http://127.0.0.1:8000/admin`. Самостоятельные нормативные акты: `/acts`. Структура кодекса: `/admin/hierarchy`. Категории: `/admin/categories`. Отношения: `/admin/relations`. Архив: `/admin/archive`. Журнал: `/admin/audit`.

Исторические редакции сохраняют снимки названий юридических справочников начиная со схемы v2. Внешние ведомственные публикации не становятся нормативными актами до явного подтверждения суперадминистратором.

## Как создать кодекс и настроить категории

Запустите start_portal.bat, выберите роль «Суперадминистратор» и откройте «Каталог законов». Нажмите **«＋ Создать кодекс»** (или откройте /admin/codes и ту же команду). В форме введите имя, краткое обозначение и уровень права. По умолчанию предлагается структура «Часть → Раздел → Глава → Подраздел», которую можно изменить позднее. При желании выберите пустую структуру. Реквизиты публикации (орган, номер/источник и дата) необязательны; их можно добавить позднее. После сохранения откроется страница кодекса, в которой доступны создание разделов и статей.

Чтобы настроить категории, откройте /admin/categories. Слева находится поиск и список категорий; справа — сведения одной выбранной категории. «＋ Новая категория» создаёт запись, а «＋ Добавить поле» добавляет дополнительный параметр. Для настройки поля раскройте его строку, затем задайте тип и, если нужен список, значения справочника. Применявшиеся ранее поля защищены от несовместимого изменения типов.

Для обновления уже созданной локальной базы **не удаляйте SQLite-файл**: после git pull и перезапуска автоматически применяются миграции схемы, включая версию v4 для реквизитов публикации кодексов.

## Управление структурой и юридическими связями

Под ролью «Суперадминистратор» откройте /admin/hierarchy. Выберите кодекс и затем одну из задач: «Уровни структуры», «Переместить раздел» или «Порядок разделов». В первом разделе выбирайте тип в компактном списке и настраивайте его допустимых родителей; для исключения используйте предварительную проверку последствий. Перенос разделов и сортировка выполняются отдельно, а постоянные ссылки на статьи при перемещении сохраняются.

В /admin/relations доступны самостоятельные задачи «Виды и правила», «Связать статьи», «Просмотр и восстановление». Сначала настройте допустимые категории источника и цели, затем найдите нужные статьи по номеру или названию. Отключённые юридические связи можно восстанавливать по одной и только после серверной проверки совместимости.

Классы правонарушений в формах и поиске отображаются на русском: «Тяжкое преступление» (felony), «Проступок» (misdemeanor), «Нарушение» (infraction); в базе продолжают храниться неизменные ID. Читательская боковая навигация подгружает разделы порциями, поэтому открытие большого кодекса не требует загрузить всю его иерархию. Для надёжности применяется строгая политика безопасности браузера CSP.

## Восстановление БД и эксплуатация

`scripts/db_maintenance.py` поддерживает проверяемую резервную копию SQLite, восстановление с аварийной резервной копией, проверку целостности и запуск миграций. Перед восстановлением сервер нужно остановить. Полный порядок, параметры OIDC и настройки сервисного API описаны в [docs/OPERATIONS.md](docs/OPERATIONS.md).

Для разработки поддерживаются три видимые роли библиотеки и отдельные тестовые учётные записи Сената. Внешняя авторизация OIDC реализована как настраиваемый PKCE-адаптер; окончательное подключение требует контракт поставщика IAM и совместные испытания. Промышленная инфраструктура требует отдельной настройки.

## Быстрый запуск

Требуется Python 3.11+.

    python -m venv .venv
    source .venv/bin/activate
    pip install -e ".[test]"
    uvicorn app.main:app --reload

Сайт: http://127.0.0.1:8000
OpenAPI: http://127.0.0.1:8000/docs
Тестирование: pytest -q

В пользовательском интерфейсе библиотеки доступны три роли: читатель (user), юрист (lawyer), суперадминистратор (superadmin). Внутренние серверные роли ведомственных процессов сохранены до разработки отдельных сайтов.
В продуктивном окружении тестовые аккаунты отключены и требуется внешний OIDC.

Информация об API, серверной модели, ограничениях и необходимых доработках: [docs/IMPLEMENTATION.md](docs/IMPLEMENTATION.md).

**Статус:** пилотный функциональный фундамент, не завершённая промышленная реализация всего ТЗ 1.0.

Пользовательские доработки по замечаниям UI-001…UI-008: [docs/UI_FEEDBACK_TZ.md](docs/UI_FEEDBACK_TZ.md). Для работы со структурой кодекса выберите роль «Суперадминистратор», откройте кодекс и воспользуйтесь кнопками «Добавить тип уровня» и «Добавить часть / раздел».

## Penal Code: подготовленная часть I

Файл `data/pen_part_i.json` содержит предоставленные исходные материалы: одну часть
«О преступлениях и наказаниях», 18 разделов и 104 статьи. При запуске из
`start_portal.bat` локальная библиотека автоматически импортирует эти материалы
один раз в существующий Penal Code (или создаёт кодекс, если он отсутствует).
Повторный запуск не дублирует и не перезаписывает статьи или их редакции.
Импорт атомарен: при конфликте номера статьи операция отменяется.

Для запуска через обычный `uvicorn` можно задать
`AUTO_IMPORT_PENAL_PART_I=1` в локальном окружении либо выполнить импорт вручную:

```bash
python -m scripts.import_penal_part_i
python -m scripts.import_penal_part_i --apply
```

В первой команде показан состав источника без изменений БД, вторая выполняет
импорт с проверкой конфликтов. Можно передать `--database путь/к/базе.sqlite`.
**В production автоматический импорт выключен**: сначала необходимо выполнить
резервное копирование, редакционную проверку и затем явный запуск `--apply`.

В файле нет обязательных уголовно-правовых классов для 76 статей категории
«Обвинение». При импорте им назначается временная категория
«Обвинение — требуется указать уголовно-правовой класс» вместо автоматического
создания недостоверного значения felony/misdemeanor/infraction. Исходная категория
каждой статьи записывается в сведениях происхождения первой редакции.
25 вспомогательных норм получают отдельную одноимённую категорию, а 3
отягчающих обстоятельства — соответствующую имеющуюся категорию.
Все импортированные статьи помечены как материалы без подтверждённой
официальной публикации; юридические тексты и санкции не дополняются догадками.

## Хранение административного журнала

Внутренние события `audit_events` библиотеки, которым исполнилось более **шести
календарных месяцев**, автоматически удаляются при запуске сервера и затем
раз в сутки в работающем процессе. Отсчёт выполняется по времени UTC.
История редакций законов, архив, юридические связи и тексты статей при такой
очистке не затрагиваются. Рекомендуется заранее учесть резервирование и
требования внешнего аудита; восстановить удалённые события из живой БД нельзя.
События Сената с префиксом `senate.` и отдельный журнал `senate_audit` не удаляются этой процедурой.

## Обновление Сената по фидбеку

Редактор поддерживает отдельный выбор авторов и соавторов среди сенаторов, реквизиты шапки, две части резолюции и клаузы WHEREAS/RESOLVED. История показывает имена и описания действий. Страница заседаний объединяет пленарные и комитетские повестки, фильтры, адреса и свободные обсуждения. При переносе открытого заседания голосование начинается заново; прежние бюллетени сохраняются отдельным раундом.

После обновления исходников перезапустите портал через `start_senate.bat`. Миграции 15–16 применяются при запуске. Penal Code получает ID `PEN` с сохранением связей статей и прежних редакций. Подробности и история требований находятся в [документации фидбека](docs/senate/FEEDBACK_2026-11-06.md).
